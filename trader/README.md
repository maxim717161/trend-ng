# Пробный торговый бот NGM (лимитные заявки, 1 лот, Яндекс Облако)

Пробный запуск для месячного сбора реальных данных об исполнении. **Это не проверенная прибыльная стратегия**: исследование (ветки `cursor/trend-hypothesis`, `cursor/momentum-hypothesis`) не нашло статистически значимого преимущества, цель запуска - узнать, что реально происходит с лимитными заявками, проскальзыванием и результатом на новых данных.

## Что делает

- Раз в минуту (триггер-таймер) запускается функция `trader.handler.handler`.
- Торгует **один лот** фьючерса NGM (`NR*`) с ближайшей экспирацией, до которой больше 3 дней; за 3 дня до экспирации закрывает позицию и переходит на следующий контракт.
- Сигнал (`strategy.py`): моментум-ансамбль на часовых барах: знак изменения цены закрытия за 72, 96, 120 и 166 часовых баров (это окна 4320-10000 минут из исследования моментума). Позиция +1/-1 при согласии >= 3 из 4 голосов, иначе прежняя позиция. Решение принимается один раз в час по закрытому бару. Доля торговли: в среднем около 8 сделок в месяц.
- Исполнение только лимитными заявками:
  1. пассивная заявка по лучшей цене своей стороны (покупка по bid, продажа по ask), раз в 5 минут переставляется к новой лучшей цене;
  2. через 30 минут после решения - «маркетабельная» лимитка по цене противоположной стороны (пересекаем спред), переставляется раз в минуту;
  3. при спреде шире 30 тиков пассивная заявка не ставится.
- Всё пишется в бакет Object Storage: `state.json` (состояние) и `logs/<дата>/<время>_<n>.jsonl` (события: heartbeat раз в час, decision, order_placed, order_cancel, fill, order_done, error, safety_halt и т.д.).

## Что ожидать (бэктест того же правила, `python3 -m trader.backtest`, 22 контракт-месяца, `reports/trader_backtest_output.txt`)

| | gross | net 0 б.п. | net +2 б.п. на сторону | net +5 б.п. на сторону |
|---|---|---|---|---|
| среднее за месяц, % номинала | +3.2 | +2.5 | +2.2 | +1.8 |
| медиана, % | +1.2 | +0.6 | +0.3 | -0.3 |
| без NRF6 (среднее), % | +1.0 | +0.3 | 0.0 | -0.5 |

Плюсовых месяцев ровно половина (11 из 22), разброс огромный: стандартное отклонение месяца 15.7% номинала одной ноги, лучший месяц +49% (`NRF6`), худший -17.5%; по пяти хронологическим группам среднее net: +3.8, +1.1, +13.5, +0.9, -6.9%. То есть за один месяц результат в основном определяется случайностью направления, а не качеством исполнения. Поэтому главное, что стоит смотреть через месяц, - не прибыль, а:

- разницу между ценой исполнения и mid на момент решения (`slippage_bps`), долю пассивных исполнений, время от решения до исполнения;
- совпадение позиции бота с сигналом, число сбоев и остановок;
- реальную комиссию и расхождения с оценкой 0.05% за сторону.

## Слои защиты

- По умолчанию `MODE=paper`: заявки не отправляются, исполнение симулируется по реальному стакану (пессимистично: лимитка исполняется только когда рынок дошёл до цены). Боевой режим требует `MODE=live`, `LIVE_CONFIRM=I_UNDERSTAND`, `TINVEST_ACCOUNT_ID` и `EQUITY_FLOOR_RUB > 0`.
- Лимит позиции: не больше 1 лота (`MAX_LOTS` другим быть не может); при позиции больше лимита бот останавливается.
- Позиция брокера - источник истины: если она два тика подряд не совпадает с учётом по нашим исполнениям (ручная сделка, сбой, неверный знак), бот останавливается (`safety_halt`) и ничего не делает, пока вы не вмешаетесь.
- Порог стоимости счёта `EQUITY_FLOOR_RUB`: ниже него позиция закрывается и бот останавливается.
- Идемпотентность заявок (UUID сохраняется в состоянии до отправки), сбой в тике не роняет функцию: ошибка пишется в лог.
- Рубильники в бакете (создайте пустой объект): `<prefix>control/halt` - остановить торговлю и снять заявку (позицию бот не трогает), `<prefix>control/flatten` - закрыть позицию и не открывать новых.
- Торгует только в окнах 09:05-13:55, 14:10-18:40, 19:10-23:45 МСК по будням и только когда брокер сообщает нормальный статус торгов.

## Что не проверено (прочитайте до запуска)

1. Адаптер T-Invest (`tinvest.py`) написан по документации REST API и покрыт тестами на ответах-заглушках, но **на реальном счёте не запускался**. Особенно проверьте: знак позиции в `GetPositions` (шорт должен быть отрицательным), цену исполнения (`averagePositionPrice`), формат тикера (`NRV6`), размер часовых свечей. Для этого есть `python -m trader.run_local selfcheck` (только чтение). Если брокер у вас другой, нужно написать адаптер (интерфейс в `broker.py`, 9 методов).
2. Бэктест не учитывает спред и проскальзывание, лимитные заявки могут не исполниться, а исполнение «по цене пассивной заявки» часто бывает при неблагоприятном движении цены (adverse selection).
3. Праздничные дни и сокращённые сессии определяются только статусом торгов брокера.
4. Параллельные вызовы функции не блокируются; чтобы они не пересекались, лимит выполнения функции стоит 50 секунд при запуске раз в минуту.
5. После перехода на следующий контракт его собственная история может быть короткой: пока баров меньше 167, голоса за недостающие окна нулевые, и вход возможен по меньшему числу согласных голосов (минимум два при двух доступных окнах). В первые дни после ролловера сигнал менее надёжен; смотрите в логах поле `bars` у событий `decision`.
6. Маржа: один лот должен помещаться в ГО с большим запасом, иначе брокер может принудительно закрыть позицию.

## Развёртывание в Яндекс Облаке

Нужны: `yc` (CLI), бакет Object Storage, сервисный аккаунт со статическим ключом доступа, токен T-Invest (для paper достаточно токена только для чтения).

```bash
# 1. бакет и сервисный аккаунт со статическим ключом
yc storage bucket create --name ngm-trader-<уникальный-суффикс>
yc iam service-account create --name ngm-trader-sa
yc resource-manager folder add-access-binding <folder-id> --role storage.editor --subject serviceAccount:<sa-id>
yc iam access-key create --service-account-name ngm-trader-sa     # сохранить key_id и secret

# 2. секреты (Lockbox), чтобы не держать токены в переменных окружения открытым текстом
yc lockbox secret create --name ngm-trader --payload '[{"key":"TINVEST_TOKEN","text_value":"<token>"},{"key":"S3_ACCESS_KEY_ID","text_value":"<key_id>"},{"key":"S3_SECRET_ACCESS_KEY","text_value":"<secret>"}]'
yc lockbox secret add-access-binding --name ngm-trader --service-account-name ngm-trader-sa --role lockbox.payloadViewer

# 3. сборка пакета (из корня репозитория) и загрузка через бакет (архив больше лимита прямой загрузки)
trader/deploy/build.sh
yc storage s3api put-object --bucket ngm-trader-<суффикс> --key deploy/ngm-trader.zip --body build/ngm-trader.zip

# 4. функция (сначала paper)
yc serverless function create --name ngm-trader
yc serverless function version create --function-name ngm-trader --runtime python311 \
  --entrypoint trader.handler.handler --memory 128m --execution-timeout 50s \
  --service-account-id <sa-id> \
  --package-bucket-name ngm-trader-<суффикс> --package-object-name deploy/ngm-trader.zip \
  --environment MODE=paper,S3_BUCKET=ngm-trader-<суффикс>,S3_PREFIX=ngm-trader/ \
  --secret name=ngm-trader,key=TINVEST_TOKEN,environment-variable=TINVEST_TOKEN \
  --secret name=ngm-trader,key=S3_ACCESS_KEY_ID,environment-variable=S3_ACCESS_KEY_ID \
  --secret name=ngm-trader,key=S3_SECRET_ACCESS_KEY,environment-variable=S3_SECRET_ACCESS_KEY

# 5. таймер раз в минуту (cron в UTC, формат Яндекса: минуты часы день месяц день-недели год)
yc serverless trigger create timer --name ngm-trader-every-minute --cron-expression '* * * * ? *' \
  --invoke-function-name ngm-trader --invoke-function-service-account-id <sa-id>
```

Синтаксис флагов `yc` проверьте по `yc serverless function version create --help` для вашей версии CLI.

Порядок включения:

1. Локально: `export TINVEST_TOKEN=... ; python -m trader.run_local selfcheck` - убедиться, что счёт, контракты, стакан, свечи и сигнал читаются, и что часовых баров хватает (нужно 167 завершённых).
2. Paper на неделю-две: смотреть `state.json` и логи в бакете; `python -m trader.run_local once` (локальная папка `trader_local/`) для отладки.
3. Боевой режим: создать новую версию функции с `MODE=live,LIVE_CONFIRM=I_UNDERSTAND,TINVEST_ACCOUNT_ID=<id>,EQUITY_FLOOR_RUB=<порог>` и токеном с правом торговли. Первые часы следить за логом и позицией в приложении брокера.

Снять остановку после `safety_halt`: убрать причину (сверить позицию вручную), в `state.json` обнулить `safety_halt` (`null`) и `mismatch_n` (0), при остановке по порогу счёта - `flatten_reason` (`null`), удалить объекты `control/halt`/`control/flatten`.

## Разбор через месяц

```bash
export S3_BUCKET=... S3_ACCESS_KEY_ID=... S3_SECRET_ACCESS_KEY=... S3_PREFIX=ngm-trader/
python -m trader.report            # сводка + report_events.csv, report_fills.csv
```

Сводка показывает: решения и смены позиции, исполнения, долю пассивных, проскальзывание к mid на момент решения (б.п., плюс = дороже), время до исполнения, замкнутые сделки в % от цены входа с оценкой комиссии 0.05% за сторону, ошибки и остановки. Сравнивать с бэктестом надо на тех же днях: `python -m trader.backtest` считает по загруженным минуткам (`trend_ng/download.py`).
